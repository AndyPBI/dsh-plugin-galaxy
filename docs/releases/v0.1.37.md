# dsh-plugin-galaxy 0.1.37

修复桌面版**所有写操作都报 `untrusted origin`**（面板能看、不能安装/更新/启停/卸载）。

## 原因

报错来自本插件自己的同源守卫（`src/api/router.ts`，所有 POST 默认 `sameOrigin: true`）。
打包桌面壳在把应用请求转发给宿主时，会**删除 `origin`/`host`/`cookie`/`sec-fetch-site`** 并注入宿主自己的认证 cookie
（`apps/desktop/src/web-document.ts` → `forwardWebRequest`）。旧判定要求 `Origin` 必须存在且与 `Host` 一致，
于是桌面 UI 的每个写请求都是「裸请求」→ 403。

与国内网络、GitHub 都无关（请求根本没出机器）；浏览器形态（开发版 `http://127.0.0.1:3080`）`Origin` 正常，
所以开发版没暴露这个问题。**macOS 桌面版同样会中**，只是之前没测到写操作。

## 修复

`sameOrigin()` 在**回环**前提下多接受两种形态：

| 情形 | 判定 |
|---|---|
| `Origin` 与 `Host` 一致 | 允许（不变） |
| **无 `Origin` 且来自回环** | 允许（桌面壳的转发形态） |
| `Origin` 为 `dsh-app://` 协议且来自回环 | 允许（若某些壳版本原样转发 app origin） |

安全性不降级：后两条都额外要求 socket 来自回环；浏览器在跨源 POST 上必然带 `Origin`，所以「缺失」本身就有意义；
`Origin: null`（沙箱 iframe / `file://`）仍拒绝；破坏性路由（重启/自我卸载/备份下载）本来还要求 loopback。

## 影响面

桌面版的**安装、更新、卸载、启停、备注、收藏、快照/恢复、通道/区域、目录来源**恢复可用；浏览器形态行为不变。
